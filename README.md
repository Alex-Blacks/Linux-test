## Базовые команды и навигация

**Запуск от имени супер пользователя(Администратора):**
```bash
sudo  # приставка в начале любой команды
```

**Показать текущую директорию:**
```bash
pwd
```

**Выполнить предыдущую команду:**
```bash
!!
```

**Вывести информацию о системе и ядре:**
```bash
uname -a
```

**Вывести список файлов и папок:**
```bash
ls
ls -la
```
Разбор вывода прав доступа (`-rw-rw-r--`):
* Первый символ (`-` или `d`) — тип объекта (`-` обычный файл, `d` директория).
* Первые 3 символа (`rw-`) — права **владельца**: `r` (чтение), `w` (запись), `x` (выполнение, `-` значит запрещено).
* Вторые 3 символа (`rw-`) — права **группы**.
* Последние 3 символа (`r--`) — права **всех остальных**.

**Показать дерево каталогов и файлов:**
```bash
tree
```

**Перемещение по папкам:**
```bash
cd /путь/к/папке   # перейти по пути
cd ~               # перейти в домашнюю директорию
cd ..              # вернуться на одну папку назад
```

**Очистить экран терминала:**
```bash
clear
```

**Посмотреть историю:**
```bash
history
```

## Пользователи

**Показать активных пользователей:**
```bash
w
id               # показать UID, GID и все группы текущего пользователя
id username      # показать группы конкретного пользователя
groups           # краткий список групп текущего пользователя
```

**Показать переменные окружения:**
```bash
env
```

**Добавить нового пользователя:**
```bash
sudo useradd -m -s /bin/bash имя_пользователя
```
* `-m` — создать домашнюю директорию (`/home/имя_пользователя`)
* `-s` — задать оболочку (`/bin/bash` — стандартная)
* `-d` — указать путь к домашнему каталогу вручную
* `-G` — добавить в дополнительные группы
  
**Удалить пользователя:**
```bash
sudo userdel имя_пользователя
```

**Изменить пароль пользователя:**
```bash
sudo passwd имя_пользователя
```

**Создать группу:**
```bash
sudo groupadd название_группы
```

**Добавить пользователя в группу:**
```bash
sudo gpasswd -a имя_пользователя название_группы
```
> **Важно:** если не поставить флаг `-a`, команда удалит пользователя из всех остальных групп кроме добавленной.

**Просмотреть группы:**
```bash
sudo getent group название_группы
```
 
**Поменять пользователя:**
```bash
su - имя_пользователя
```
* `-` — делает полную смену пользователя (с загрузкой его окружения)

**Поменять владельца и группу для папки/файла:**
```bash
sudo chown -R root:alex file.txt
```
* `-R` — поменять и у объектов внутри

**Поменять разрешения папки или файла:**
```bash
sudo chmod -R 664 папка_или_файл
```
* `-R` — рекурсивное изменение прав для папки и всего содержимого.
| Цифра | Права | Расшифровка |
| :---: | :---: | :--- |
| **7** | `rwx` | Полный доступ (чтение, запись, выполнение) |
| **6** | `rw-` | Чтение и запись |
| **5** | `r-x` | Чтение и выполнение |
| **4** | `r--` | Только чтение |
| **3** | `-wx` | Запись и выполнение |
| **2** | `-w-` | Только запись |
| **1** | `--x` | Только выполнение |
| **0** | `---` | Нет прав |

* Спецбиты (ставятся четвертой цифрой в начале, например `4755`): `4` — SUID, `2` — SGID.

**Поменять группу у файла:**
```bash
sudo chgrp whales myfile
```

**Поменять набор разрешений по умолчанию:**
```bash
Umask
```

## Systemd (Управление службами и автозагрузкой)

**Управление состоянием службы (на примере `nginx`):**
```bash
sudo systemctl status nginx          # проверить статус, PID и последние строки логов службы
sudo systemctl start nginx           # запустить службу
sudo systemctl stop nginx            # остановить службу
sudo systemctl restart nginx         # полностью перезапустить службу
sudo systemctl reload nginx          # перечитать конфиг без разрыва текущих соединений
```

**Управление автозагрузкой при старте системы:**
```bash
sudo systemctl enable nginx          # включить автозапуск при загрузке ОС
sudo systemctl disable nginx         # убрать из автозагрузки
sudo systemctl enable --now nginx    # включить автозагрузку и сразу запустить службу
```

**Диагностика и обновление конфигурации:**
```bash
sudo systemctl daemon-reload                             # перечитать файлы юнитов после их правки
sudo systemctl list-units --type=service --state=running # список всех работающих служб
sudo systemctl list-units --type=service --state=failed  # показать службы, упавшие с ошибкой
```

## Мониторинг процессов

**Диспетчер задач:**
```bash
top
```
Горячие клавиши внутри `top`:
* `P` — сортировать по CPU
* `M` — сортировать по памяти
* `T` — сортировать по времени работы
* `f` — изменить порядок столбцов
* `W` — сохранить конфигурацию в `~/.toprc`

**Улучшенная версия `top`:**
```bash
htop
```

**Показать сообщения ядра с человекочитаемым временем:**
```bash
dmesg -T         # полезно при сбоях дисков и OOM Killer
```

**Показать информацию об используемой памяти:**
```bash
free
free -h   # переводит байты в мега/гигабайты
```

**Показать запущенные процессы:**
```bash
ps        # процессы текущего пользователя
ps aux    # все процессы всех пользователей
```

**Завершить процесс:**
```bash
kill PID_процесса
kill -9 PID_процесса   # принудительное (мгновенное) завершение
```

**Установить приоритет для нового процесса (при запуске):**
```bash
nice -n 10 команда
```
Диапазон приоритетов: от `-20` (максимальный) до `19` (минимальный).

**Изменить приоритет для уже запущенного процесса:**
```bash
renice -n 5 -p PID_процесса
```

**Запустить процесс в фоновом режиме:**
```bash
команда &
```
> **Важно:** Если процесс уже запущен на переднем плане, нажмите `Ctrl+Z` (приостановить) и введите `bg` (отправить в фон).

**Просмотреть фоновые задачи:**
```bash
jobs
```

**Показать системные вызовы, которые делает процесс:**
```bash
strace команда          # запустить и отследить новую команду
strace -p PID_процесса  # подключиться к уже запущенному процессу
```

**Показать открытые файлы и связанные с ними процессы:**
```bash
lsof
sudo lsof -u alex           # только файлы определённого пользователя
sudo lsof /var/log/syslog   # кто использует конкретный файл
sudo lsof -i :80            # кто слушает конкретный порт (например, 80)
```

**Показать процесс или пользователя, использующего файл:**
```bash
fuser /путь/к/файлу
```

**Показать время работы системы и среднюю загрузку (Load Average):**
```bash
uptime
```

**Отслеживать использование ЦП и дисков:**
```bash
iostat
```

**Отслеживать использование памяти и подкачки:**
```bash
vmstat
```

**Непрерывный мониторинг активности системы:**
```bash
sudo sar
sudo sar -q   # очередь процессов и нагрузка с начала дня
sudo sar -r   # использование памяти с начала дня
sudo sar -P   # использование ЦП с начала дня
```
Посмотреть статистику за другой день (где `02` — число месяца):
```bash
sar -q -f /var/log/sysstat/sa02
```

**Редактировать планировщик задач Cron:**
```bash
crontab -e
```
Пример задания (удалять бэкапы старше 7 дней каждый день в 03:00):
```cron
0 3 * * * find /home/alex/backups -type f -mtime +7 -name "*.tar.gz" -delete
```
Расшифровка пяти звёздочек (`* * * * *`):
1. `0–59` — Минуты
2. `0–23` — Часы
3. `1–31` — День месяца
4. `1–12` — Месяц
5. `0–7` — День недели (`0` и `7` — воскресенье)

## Работа с файлами

### 1. Создание, копирование и удаление

**Создать пустой файл (можно несколько через пробел):**
```bash
touch файл.txt
touch файл1.txt файл2.txt
```
> **Примечание:** В Linux расширение (`.txt`) указывать не обязательно, но желательно для удобства.

**Создать или отредактировать файл в консольном редакторе:**
```bash
nano файл.txt
```

**Создать папку:**
```bash
mkdir папка
mkdir -p папка1/папка2/папка3   # создать всю цепочку вложенных папок
```

**Копировать файл или папку:**
```bash
cp файл.txt папка/              # скопировать с тем же именем
cp файл.txt папка/новое_имя.txt # скопировать и переименовать
cp -r папка1/ папка2/           # скопировать папку со всем содержимым
```

**Переместить или переименовать файл/папку:**
```bash
mv файл.txt папка/              # переместить в папку
mv старое_имя.txt новое_имя.txt # переименовать
```

**Удалить файл или папку:**
```bash
rm файл.txt       # удалить конкретный файл
rm *              # удалить все файлы в текущей папке (папки не тронет)
rm -rf папка/     # принудительно удалить папку со всем содержимым
```

**Определить реальный тип/формат файла (независимо от расширения):**
```bash
file файл
```

### 3. Поиск, просмотр и обработка текста

**Поиск файлов и папок (`find`):**
```bash
find . -type f -name "имя_файла"
```
* `.` — искать в текущей директории (можно указать любой путь, например `/var/log`)
* `-type f` — искать только файлы (`-type d` — только директории)
* `-name` — поиск по точному имени (`-iname` — без учета регистра)
* `-size +100M` — поиск по размеру (например, файлы больше 100 МБ)
* `-perm 644` — поиск по правам доступа
* `-not` — инвертировать условие (найти всё, что НЕ подходит под критерий)
* `-exec команда {} +` — выполнить указанную команду над найденными файлами (например, запустить `grep` внутри найденных файлов)

**Сделать файл/скрипт исполняемым:**
```bash
  chmod +x script.sh 
```

**Вывести содержимое файла целиком:**
```bash
cat файл.txt
less /var/log/syslog   # постраничный просмотр больших файлов (выход — клавиша q, поиск — /текст)
```

**Вывести начало или конец файла:**
```bash
head -n 10 файл.txt   # первые 10 строк (по умолчанию 10)
tail -n 10 файл.txt   # последние 10 строк
tail -f /var/log/syslog   # следить за новыми строками в реальном времени
```

**Просмотр системных логов `systemd`:**
```bash
sudo journalctl --since "10 min ago"   # логи за последние 10 минут
sudo journalctl -k                     # только сообщения ядра
sudo journalctl -f                     # вывод новых логов в реальном времени
```

**Поиск текста внутри файлов (`grep`):**
```bash
grep -n "Error" logs/app.log
```
* `-n` — показывать номера найденных строк
* `-i` — игнорировать регистр букв

**Регулярные выражения (для `grep` и поиска):**
* `^by` — строка начинается с `by`
* `by$` — строка заканчивается на `by`
* `b.` — символ `b` и любой один символ после него (`ba`, `bo`, `b1`)

**Извлечение и обработка колонок текста (`awk`, `cut`):**
```bash
awk '{print $1}' file.txt   # вывести первый столбец из файла
cut -d':' -f1 /etc/passwd   # извлечь часть строки по разделителю
```

**Сортировка и фильтрация дубликатов:**
```bash
sort file.txt          # сортировка по алфавиту
sort -n file.txt       # корректная сортировка чисел
sort -r file.txt       # сортировка в обратном порядке
uniq file.txt          # удалить дубликаты (только если они идут подряд!)
sort file.txt | uniq   # правильно: сначала отсортировать, потом убрать дубли
```
Флаги для `uniq`:
* `-c` — посчитать количество повторений каждой строки
* `-u` — вывести только уникальные строки
* `-d` — вывести только дублирующиеся строки

**Подсчет строк, слов и байтов:**
```bash
wc file.txt      # строки, слова, байты
wc -l file.txt   # только количество строк
wc -w file.txt   # только количество слов
wc -c file.txt   # только количество байтов
nl file.txt      # вывести содержимое файла с нумерацией строк
```

**Другие полезные утилиты для текста:**
* `tr 'a-z' 'A-Z'` — замена символов (например, перевод строчных букв в заглавные)
* `paste file1.txt file2.txt` — объединить строки двух файлов построчно
* `join file1.txt file2.txt` — объединить два файла по общему полю
* `split -l 100 bigfile.txt` — разбить большой файл на части по 100 строк
* `expand` / `unexpand` — конвертировать табуляцию в пробелы и обратно

**Перенаправление ввода/вывода и конвейеры (`|`):**
```bash
echo "hello" > text.txt    # записать в файл (перезапишет, если файл есть)
echo "hello" >> text.txt   # дописать в конец файла
команда 2> errors.log      # записать только ошибки (перезапись)
команда 2>> errors.log     # дописать только ошибки в конец файла
команда &> all.log         # записать и обычный вывод, и ошибки (перезапись)
команда &>> all.log        # дописать и вывод, и ошибки в конец файла
sort < items.txt           # передать содержимое файла на вход команде
```
* `команда1 | команда2` — **конвейер (pipe)**: результат первой команды передается на вход второй.
* `команда | tee file.txt` — вывести результат на экран и одновременно сохранить в файл.

### 4. Архивация и сжатие

**Работа с `.tar` (объединение файлов в один архив без сжатия):**
```bash
tar cf folder.tar test/   # создать архив folder.tar из папки test
tar tf folder.tar         # посмотреть содержимое архива без распаковки
tar xf folder.tar         # распаковать архив
```

**Создать сжатый архив `.tar.gz` одной командой:**
```bash
tar cvzf folder.tar.gz test/
```
* `c` — create (создать архив)
* `v` — verbose (показывать процесс в терминале)
* `z` — gzip (сжать алгоритмом gzip)
* `f` — file (указать имя итогового файла архива)

**ZIP-архивы:**
```bash
zip -r folder.zip test/   # заархивировать папку рекурсивно (-r)
unzip folder.zip          # распаковать zip-архив
```

**Другие утилиты сжатия отдельных файлов:**
* `gzip файл` / `gunzip файл.gz` — сжатие/распаковка `.gz`
* `bzip2 файл` / `bunzip2 файл.bz2` — сжатие/распаковка `.bz2`
* `xz файл` / `unxz файл.xz` — сжатие/распаковка `.xz`

## Работа с дисками

### 1. Разметка дисков (`parted`)

**Показать все диски, разделы и точки монтирования деревом:**
```bash
lsblk 
```

**Запустить интерактивную утилиту разметки дисков (поддерживает MBR и GPT):**
```bash
sudo parted
```
Команды внутри интерактивной оболочки `(parted)`:
```text
select /dev/sdb             # выбрать диск для работы (именно диск, не раздел)
mkpart primary 123 4567     # создать раздел (указывается тип, начало и конец в МБ)
resizepart 2 3456           # изменить размер раздела №2 (указать новую конечную точку)
```

---

### 2. Файловые системы и монтирование

**Отформатировать раздел в нужную файловую систему (например, `ext4`):**
```bash
sudo mkfs -t ext4 /dev/sdb2
```

**Посмотреть UUID (уникальные идентификаторы) всех дисков и разделов:**
```bash
sudo blkid
```

**Примонтировать раздел в папку:**
```bash
sudo mount -t ext4 /dev/sdb2 /mydrive
sudo mount UUID=130b882f-7d79-436d-a096-1e594c92bb76 /mydrive   # безопасное монтирование по UUID
```

**Постоянное монтирование диска после перезагрузки (`/etc/fstab`):**
Чтобы примонтированный диск не отвалился после ребута, добавьте строку в `sudo nano /etc/fstab`:
```text
UUID=130b882f-7d79-436d-a096-1e594c92bb76   /mydrive   ext4   defaults   0   2
```
> **Важно:** После правки `/etc/fstab` обязательно выполните `sudo mount -a` — если в файле есть ошибка, команда сразу сообщит об этом (иначе при перезагрузке система может не загрузиться).


**Отмонтировать устройство (можно указать либо папку, либо сам раздел):**
```bash

```

**Проверить и восстановить целостность файловой системы:**
```bash

```
> **Важно:** Проверять можно только **отмонтированный** раздел (и именно раздел `/dev/sda1`, а не весь диск `/dev/sda`), иначе можно повредить данные.

## SSL / TLS и сертификаты (OpenSSL)

### 1. Создание самоподписных сертификатов и CSR

**Создать самоподписной сертификат и приватный ключ одной командой (с поддержкой SAN):**
```bash
openssl req -x509 -newkey rsa:2048 -nodes \
  -keyout server.key \
  -out server.crt \
  -days 365 \
  -subj "/CN=192.168.37.131" \
  -addext "subjectAltName = IP:192.168.37.131,DNS:localhost"
```
* `-nodes` — сохранить приватный ключ без пароля (чтобы веб-сервер не запрашивал пароль при каждом перезапуске).
* `-addext` — добавить Subject Alternative Name (обязательно для современных браузеров и клиентов, без SAN сертификат для IP не примут).

**Создать запрос на подпись сертификата (CSR) и ключ для отправки в Центр сертификации (CA):**
```bash
openssl req -new -newkey rsa:2048 -nodes \
  -keyout domain.key \
  -out domain.csr \
  -subj "/C=RU/ST=Moscow/L=Moscow/O=MyCompany/CN=example.com"
```

---

### 2. Собственный локальный Центр сертификации (Local Root CA)

**1. Создать корневой ключ и корневой сертификат на 10 лет:**
```bash
openssl genrsa -out myCA.key 4096
openssl req -x509 -new -nodes -key myCA.key -sha256 -days 3650 \
  -out myCA.crt \
  -subj "/CN=My Local Root CA"
```
> Файл `myCA.crt` нужно один раз добавить в доверенные корневые сертификаты вашей ОС или браузера.

**2. Создать ключ и запрос (CSR) для конкретного сервера:**
```bash
openssl req -new -newkey rsa:2048 -nodes \
  -keyout app.key \
  -out app.csr \
  -subj "/CN=192.168.37.131"
```

**3. Подписать сертификат сервера вашим корневым сертификатом (с указанием SAN):**
```bash
openssl x509 -req -in app.csr -CA myCA.crt -CAkey myCA.key -CAcreateserial \
  -out app.crt -days 365 -sha256 \
  -extfile <(printf "subjectAltName=IP:192.168.37.131,DNS:app.local")
```

---

### 3. Проверка и диагностика сертификатов

**Локальная проверка файлов ключа и сертификата:**
```bash
openssl x509 -in server.crt -text -noout   # полная информация (срок действия, кому выдан, SAN)
openssl x509 -in server.crt -noout -dates  # только даты начала и окончания действия
openssl rsa -in server.key -check -noout   # проверить приватный ключ на корректность
```

**Убедиться, что сертификат и приватный ключ подходят друг к другу (MD5-хеши должны совпасть):**
```bash
openssl x509 -noout -modulus -in server.crt | openssl md5
openssl rsa -noout -modulus -in server.key | openssl md5
```

**Проверка удаленного сервера и тестирование через `curl`:**
```bash
# Посмотреть цепочку сертификатов и параметры TLS на сервере
openssl s_client -connect 192.168.37.131:443 -servername 192.168.37.131 </dev/null

# Узнать дату истечения сертификата на удаленном сайте
echo | openssl s_client -servername example.com -connect example.com:443 2>/dev/null | openssl x509 -noout -dates

# Проверить API с указанием своего самоподписного сертификата
curl --cacert /etc/nginx/ssl/server.crt https://192.168.37.131

# Проверить API, игнорируя ошибки сертификата
curl -k https://192.168.37.131
```

### 4. Конвертация форматов и добавление в доверенные ОС

**Собрать сертификат и ключ в единый контейнер `.pfx` / `.p12` (для Windows, IIS, Java):**
```bash
openssl pkcs12 -export -out bundle.pfx -inkey server.key -in server.crt
```

**Извлечь сертификат и приватный ключ из `.pfx` обратно в PEM:**
```bash
openssl pkcs12 -in bundle.pfx -clcerts -nokeys -out server.crt
openssl pkcs12 -in bundle.pfx -nocerts -nodes -out server.key
```

**Конвертировать бинарный `.der` в текстовый `.pem` (`.crt`):**
```bash
openssl x509 -inform der -in certificate.der -out certificate.crt
```

**Добавить свой сертификат в доверенные на уровне всей системы (Ubuntu / Debian):**
```bash
sudo cp server.crt /usr/local/share/ca-certificates/my-server.crt
sudo update-ca-certificates
```
> **Важно:** Файл в `/usr/local/share/ca-certificates/` обязательно должен иметь расширение `.crt`.

## Nginx (Веб-сервер и Reverse Proxy)

### 1. Основные команды управления

```bash
sudo nginx -t                  # проверить синтаксис конфигов перед перезапуском (делать всегда!)
sudo systemctl reload nginx    # применить изменения конфига без разрыва соединений
sudo systemctl restart nginx   # полный перезапуск Nginx
```

### 2. Архитектура папок в Ubuntu / Debian

* `/etc/nginx/nginx.conf` — главный конфигурационный файл.
* `/etc/nginx/sites-available/` — папка, где хранятся конфиги всех ваших сайтов.
* `/etc/nginx/sites-enabled/` — папка с символическими ссылками на активные сайты (Nginx читает конфиги именно отсюда).
* `/var/log/nginx/access.log` — лог всех входящих запросов.
* `/var/log/nginx/error.log` — лог ошибок (первым делом смотреть сюда при ошибках 500/502/504).

**Включить и выключить сайт:**
```bash
# Включить сайт (создать символическую ссылку в sites-enabled)
sudo ln -s /etc/nginx/sites-available/mysite.conf /etc/nginx/sites-enabled/

# Выключить сайт (удалить ссылку, сам файл в sites-available останется)
sudo rm /etc/nginx/sites-enabled/mysite.conf
```

### 3. Базовый шаблон Reverse Proxy (проксирование на Docker/приложение)

```nginx
server {
    listen 80;
    server_name example.com ://example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
        proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto \$scheme;
    }
}
```

## NFTables (Межсетевой экран)

### 1. Установка и управление службой

sudo apt update && sudo apt install nftables -y        # установить nftables
sudo systemctl enable --now nftables                   # включить автозагрузку службы
sudo systemctl disable --now ufw 2>/dev/null || true   # отключить старый UFW во избежание конфликтов

**Проверка, применение и безопасный тест правил:**
```bash
sudo nft -c -f /etc/nftables.conf   # проверить синтаксис файла перед запуском
sudo nft -f /etc/nftables.conf      # применить конфигурацию из файла

# Безопасный запуск со сбросом через 60 секунд (защита от потери SSH при ошибке в правилах)
sudo nft -f /etc/nftables.conf && sleep 60 && sudo nft delete table inet custom_firewall
```

---

### 2. Просмотр правил, банов и логов

```bash
sudo nft list ruleset                                  # посмотреть все активные правила в ядре
sudo nft -a list chain inet custom_firewall input      # правила цепочки input с их номерами (handle)
sudo nft list set inet custom_firewall blacklist_v4    # список забаненных IP и остаток времени бана
sudo journalctl -k -n 0 -f | grep "NFT_"               # читать логи срабатываний в реальном времени
```

---

### 3. Ручное управление банами и правилами «на лету»

> **Внимание:** Изменения через `add` / `insert` / `delete` работают сразу в памяти, но пропадут после перезагрузки, если не вписать их в `/etc/nftables.conf`.

**Работа с черным списком (`blacklist_v4`):**
```bash
sudo nft add element inet custom_firewall blacklist_v4 { 198.51.100.14 timeout 1h }   # забанить IP на 1 час
sudo nft delete element inet custom_firewall blacklist_v4 { 198.51.100.14 }             # разбанить IP досрочно
sudo nft flush set inet custom_firewall blacklist_v4                                   # очистить весь черный список
```

**Точечное управление правилами:**
```bash
# Быстро открыть порт (добавить правило в конец цепочки input)
sudo nft add rule inet custom_firewall input tcp dport 8080 accept

# Быстро заблокировать IP (вставить правило в самое начало цепочки input)
sudo nft insert rule inet custom_firewall input ip saddr 203.0.113.50 drop

# Удалить конкретное правило по его номеру handle (узнать через nft -a)
sudo nft delete rule inet custom_firewall input handle 15

# Полностью выключить фаервол (удалить нашу таблицу)
sudo nft delete table inet custom_firewall
```

---

### 4. Базовая конфигурация (`/etc/nftables.conf`)

Открыть файл конфигурации:
```bash
sudo nano /etc/nftables.conf
```

Готовый шаблон с защитой SSH от перебора паролей и изоляцией контейнеров Docker:
```nft
#!/usr/sbin/nft -f

# Удалить все таблицы flush ruleset.
# Удаляем только свою таблицу, чтобы не сломать правила Docker при перезагрузке
add table inet custom_firewall
delete table inet custom_firewall

table inet custom_firewall {
    # Динамический список для забаненных IPv4 адресов
    set blacklist_v4 {
        type ipv4_addr
        flags dynamic,timeout
        timeout 15m # Время бана: 15 минут
    }

    # Отдельный список для учета скорости попыток входа (защита от случайного самобана)
    set ssh_ratelimit {
        type ipv4_addr
        flags dynamic,timeout
        timeout 1m
    }

    chain input {
        type filter hook input priority filter; policy drop;

        # 1. Сразу отбрасываем всех, кто уже в черном списке, без логов, чтобы не спамить
        ip saddr @blacklist_v4 drop

        # 2. Базовые системные правила
        iif "lo" accept                              # разрешаем локальный интерфейс
        ct state established,related accept          # разрешаем уже установленные соединения
        ct state invalid drop                        # отбрасываем некорректные пакеты

        # 3. Разрешаем ping и служебный трафик IPv6
        ip protocol icmp accept
        ip6 nexthdr ipv6-icmp accept

        # 4. Ловушка для SSH (порт 2222)
        # Пишем в лог не чаще 5 раз в минуту, добавляем в бан и отбрасываем пакет
        tcp dport 2222 ct state new add @ssh_ratelimit { ip saddr limit rate over 4/minute } \
            limit rate 5/minute log prefix "NFT_SSH_BAN: " \
            add @blacklist_v4 { ip saddr } drop

        # 5. Разрешаем легитимный SSH и веб-трафик
        tcp dport 2222 accept
        tcp dport { 80, 443 } accept

        # 6. Молча отбрасываем локальный шум (mDNS, NetBIOS, широковещательный трафик)
        pkttype { broadcast, multicast } drop

        # 7. Логируем всё остальное, что дошло до конца цепочки и отбросится по policy drop
        limit rate 5/minute log prefix "NFT_DROP_OTHER: "
    }

    # Защита Docker (приоритет -10, выполняется ДО правил Docker)
    chain docker_guard {
        type filter hook forward priority -10; policy accept;

        # 1. Пропускаем ответный трафик для уже открытых сессий (чтобы контейнеры могли ходить в интернет)
        ct state established,related accept

        # 2. Если пакет пришел с внешнего интерфейса и идет в подсеть Docker (172.16.0.0/12)
        # ВАЖНО: заменить "ens33" на свой внешний интерфейс (посмотреть через ip -br a)
        iifname "ens33" ip daddr 172.16.0.0/12 jump docker_rules
    }

    # Отдельная цепочка с правилами доступа к контейнерам
    chain docker_rules {
        # Разрешаем доступ к контейнерам только с доверенного IP
        ip saddr 192.168.37.1 accept

        # Всё остальное, что пришло извне в контейнеры, режем
        drop
    }

    chain output {
        type filter hook output priority filter; policy accept;
    }
}
```

## SCP (Копирование файлов по SSH)

**Скопировать файл или папку между локальным ПК и удаленным сервером:**
```bash
scp myfile.txt username@remotehost.com:/remote/directory              # с локального ПК на сервер
scp username@remotehost.com:/remote/directory/myfile.txt /local/dir/   # с сервера на локальный ПК
scp -r mydir username@remotehost.com:/remote/directory                 # скопировать папку рекурсивно (-r)
```
> **Примечание:** Если SSH работает на нестандартном порту (например, `2222`), указывается заглавная буква `-P`: `scp -P 2222 myfile.txt user@host:/dir/`.

## NFS (Сетевая файловая система Linux)

**Установить клиент NFS (Ubuntu / Debian) и примонтировать удаленную папку:**
```bash
sudo apt install nfs-common                  # установка пакетов клиента NFS
sudo mount server:/directory /mount_point    # примонтировать сетевой каталог в локальную папку
```
*(В старых дистрибутивах перед монтированием мог требоваться запуск службы: `sudo service nfsclient start`).*

## Samba (Общие папки с Windows)

**Установка и первичная настройка сервера Samba:**
```bash
sudo apt install samba                 # установить Samba
sudo mkdir -p /my/directory/to/share   # создать общую директорию
sudo smbpasswd -a username             # задать пароль Samba для существующего пользователя Linux
sudo systemctl restart smbd            # перезапустить службу Samba после правки /etc/samba/smb.conf
```

**Подключение к общей папке Samba / Windows с клиента Linux:**
```bash
# Интерактивный доступ (похоже на FTP-клиент)
smbclient //HOST/directory -U username

# Примонтировать общую папку в файловую систему Linux
sudo mount -t cifs //servername/directory /mountpoint -o username=user,password=pass
```
> **Важно:** В `mount -t cifs` адрес сетевой папки пишется через двойной слеш `//servername/directory` (а не через двоеточие, как в NFS).

## Docker и Docker Compose

### 1. Работа с контейнерами

**Просмотр запущенных и всех контейнеров:**
```bash
docker ps           # только работающие контейнеры
docker ps -a        # все контейнеры (включая остановленные и упавшие)
```

**Запуск, остановка и удаление контейнеров:**
```bash
docker run -d --name my_nginx -p 8080:80 nginx   # запустить контейнер в фоне (-d) с пробросом порта
docker start имя_или_ID                          # запустить остановленный контейнер
docker stop имя_или_ID                           # мягко остановить контейнер
docker restart имя_или_ID                        # перезапустить контейнер
docker rm имя_или_ID                             # удалить остановленный контейнер
docker rm -f имя_или_ID                          # принудительно удалить работающий контейнер
```

**Логи, вход внутрь контейнера и мониторинг ресурсов:**
```bash
docker logs имя_или_ID                 # показать логи контейнера
docker logs -f --tail 100 имя_или_ID   # следить за логами в реальном времени (последние 100 строк)
docker exec -it имя_или_ID bash        # зайти в интерактивный терминал работающего контейнера (или sh)
docker stats                           # мониторинг потребления CPU и RAM контейнерами в реальном времени
```

---

### 2. Образы, тома (Volumes), сети и очистка

**Управление образами (Images):**
```bash
docker images                 # список скачанных образов на сервере
docker pull nginx:latest      # скачать образ из Docker Hub
docker rmi имя_образа         # удалить образ
docker build -t myapp:1.0 .   # собрать свой образ из Dockerfile в текущей папке
```

**Тома (Volumes) и сети (Networks):**
```bash
docker volume ls              # список томов (постоянных хранилищ данных)
docker network ls             # список сетей Docker
docker inspect имя_или_ID     # подробная техническая информация о контейнере (IP-адрес, порты, тома)
```

**Очистка сервера от «мусора» (освобождение места на диске):**
```bash
docker system df              # посмотреть, сколько места занимают образы, контейнеры и тома
docker system prune -a        # удалить все неиспользуемые контейнеры, сети и образы (осторожно!)
```

---

### 3. Docker Compose (управление стеками из `docker-compose.yml`)

> Все команды выполняются в папке, где лежит файл `docker-compose.yml`.

```bash
docker compose up -d              # поднять все сервисы в фоновом режиме
docker compose up -d --build      # пересобрать образы и запустить сервисы
docker compose down               # остановить и удалить контейнеры и сети стека
docker compose down -v            # остановить, удалить контейнеры И их тома (удалит данные БД!)
docker compose ps                 # статус контейнеров текущего проекта
docker compose logs -f            # логи всех сервисов проекта в реальном времени
docker compose logs -f web        # логи только конкретного сервиса (например, web)
docker compose restart            # перезапустить сервисы
docker compose pull               # скачать свежие версии образов для всех сервисов
```

## Git (Система контроля версий)

### 1. Первичная настройка (делается один раз на новом ПК/сервере)

```bash
git config --global user.name "Alex Blacks"
git config --global user.email "your_email@example.com"
git config --global init.defaultBranch main
```

---

### 2. Создание и клонирование репозитория

```bash
git init                                               # инициализировать новый репозиторий в текущей папке
git clone https://github.com # скачать существующий репозиторий с GitHub
```

---

### 3. Ежедневный рабочий цикл (сохранение и отправка изменений)

```bash
git status                      # проверить статус файлов (какие изменены, добавлены или не отслеживаются)
git diff                        # посмотреть построчно, что именно изменилось в файлах до коммита
git add файл.txt                # добавить конкретный файл в индекс (подготовить к коммиту)
git add .                       # добавить все измененные и новые файлы в текущей папке
git commit -m "Описание правок" # зафиксировать изменения (сделать коммит)
git push                        # отправить локальные коммиты на GitHub
git pull                        # скачать и применить свежие изменения с GitHub
```

---

### 4. Ветки и история изменений

```bash
git log --oneline -n 10         # компактная история последних 10 коммитов
git branch                      # посмотреть список локальных веток (звездочкой отмечена текущая)
git checkout -b feature-branch  # создать новую ветку и сразу переключиться на нее
git checkout main               # переключиться обратно на ветку main
git merge feature-branch        # влить изменения из ветки feature-branch в текущую ветку
```

---

### 5. Отмена ошибок

```bash
git checkout -- файл.txt        # отменить несохраненные изменения в файле (вернуть к последнему коммиту)
git reset --soft HEAD~1         # отменить последний коммит, но оставить все правки в файлах
git reset --hard HEAD~1         # жестко удалить последний коммит вместе со всеми правками (необратимо!)
```
